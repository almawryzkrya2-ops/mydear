# بيننا مجرّة — هدية عيد ميلاد تفاعلية

هذا المشروع هو موقع ويب رومانسي تفاعلي صُمم ليكون هدية عيد ميلاد رقمية. يعمل محليًا من خلال Node.js، ولا يحتاج إلى قاعدة بيانات أو مفاتيح API.

## محتويات المشروع

```text
mydear/
├── README_AR.md          ← هذا الدليل
├── package.json          ← أوامر المشروع
├── server.js             ← خادم الملفات المحلي
├── app.config.ts         ← إعداد شعار المشروع داخل Manus
├── plan.md               ← تصور التصميم والتنفيذ
├── TODO.md               ← قائمة المزايا المكتملة
└── public/
    ├── index.html        ← محتوى الصفحة وبنيتها
    ├── styles.css        ← التصميم والألوان والاستجابة
    ├── app.js            ← التفاعلات والتخصيص والرسائل
    ├── manus-routes.json ← تعريف مسارات الموقع
    └── images/           ← الصور التجريبية المحلية
```

## المتطلبات

ثبّت البرامج التالية على جهازك:

1. **Visual Studio Code** لتحرير الملفات.
2. **Node.js إصدار 18 أو أحدث**. يفضّل استخدام إصدار LTS.
3. متصفح حديث مثل Chrome أو Edge أو Firefox.
4. اتصال بالإنترنت فقط إذا أردت تحميل خطوط Google أو استخدام روابط صور خارجية؛ الموقع نفسه يعمل بالصور المحلية الموجودة داخل المشروع.

للتحقق من تثبيت Node.js افتح Terminal داخل VSCode ونفّذ:

```bash
node --version
npm --version
```

إذا ظهرت أرقام الإصدارات، فبيئتك جاهزة.

## تشغيل الموقع محليًا في VSCode

### الطريقة الأولى: باستخدام Terminal داخل VSCode

1. فك ضغط الملف `mydear-birthday.zip` في أي مكان.
2. افتح VSCode.
3. اختر **File → Open Folder** ثم اختر مجلد `mydear`.
4. افتح الطرفية من **Terminal → New Terminal**.
5. شغّل الموقع:

```bash
npm start
```

6. ستظهر رسالة مشابهة لهذه:

```text
mydear listening on 3000
```

7. افتح المتصفح على:

```text
http://localhost:3000
```

لإيقاف الموقع، ارجع إلى الطرفية واضغط:

```text
Ctrl + C
```

### الطريقة الثانية: تشغيل مباشر من ملف الخادم

إذا لم يعمل أمر `npm start`، شغّل:

```bash
node server.js
```

ثم افتح `http://localhost:3000`.

### تغيير المنفذ

إذا كان المنفذ 3000 مستخدمًا، يمكنك تشغيل الموقع على منفذ آخر.

في macOS أو Linux:

```bash
PORT=3001 npm start
```

في Windows PowerShell:

```powershell
$env:PORT=3001; npm start
```

ثم افتح:

```text
http://localhost:3001
```

## كيف تعدّل الموقع؟

### 1. تعديل الاسم والرسالة والتاريخ والصور من داخل الموقع

شغّل الموقع ثم اضغط زر **«اكتبي قصتنا»** في أعلى الصفحة.

يمكنك تعديل:

- اسم الحبيبة.
- اسمك أو توقيعك.
- تاريخ بداية العلاقة أو التاريخ المهم.
- رسالة عيد الميلاد النهائية.
- روابط الصور الثلاث.

هذه التعديلات تُحفظ في متصفحك باستخدام `localStorage`. عند نشر الموقع للعامة، الأفضل تعديل الملفات نفسها أو إدخال القيم النهائية قبل تصوير/مشاركة الرابط من نفس المتصفح.

### 2. تعديل النصوص الرئيسية

افتح الملف:

```text
public/index.html
```

يمكنك تعديل العناوين والنصوص العربية مباشرة. ابحث عن النص الذي تريد تغييره باستخدام `Ctrl + F` في Windows أو `Cmd + F` في macOS.

أهم الأقسام:

- `hero`: الافتتاحية.
- `story`: فصول القصة الأولى.
- `timeline`: خط الذكريات.
- `memories`: معرض الصور.
- `letters`: الأظرف والرسائل.
- `reasons`: الأشياء التي تحبها فيها.
- `future`: العداد والمحطة القادمة.
- `finale`: رسالة عيد الميلاد النهائية.

### 3. تعديل الألوان والتصميم

افتح:

```text
public/styles.css
```

الألوان الأساسية موجودة في بداية الملف داخل `:root`:

```css
--navy: #101a39;
--coral: #ff765c;
--cream: #f4eee3;
```

يمكنك تغييرها مع الحفاظ على التباين. كما يمكنك تعديل أحجام الخطوط والمسافات وقواعد الهاتف الموجودة داخل `@media (max-width: 800px)`.

### 4. تعديل التفاعلات والرسائل

افتح:

```text
public/app.js
```

ستجد في بداية الملف مصفوفات سهلة التعديل:

- `letters`: نصوص الأظرف الثلاثة.
- `reasons`: قائمة «أشياء أحبها فيكِ».
- `memoryCopies`: النصوص التي تظهر عند اختيار محطات الخط الزمني.
- `memories`: الصور وعناوينها.

مثال لتعديل سبب من أسباب الحب:

```js
const reasons = [
  'ابتسامتكِ عندما تكتشفين شيئًا جديدًا.',
  'طريقتكِ في جعل البيت أكثر دفئًا.'
];
```

### 5. استبدال الصور

للاستخدام المحلي، ضع صورك داخل:

```text
public/images/
```

ثم عدّل مسارات الصور في `public/app.js` مثل:

```js
const fallbackPhotos = [
  '/images/our-first-photo.jpg',
  '/images/our-trip.jpg',
  '/images/our-favorite-place.jpg'
];
```

يفضل استخدام صور بصيغة JPG أو WebP، وعرض لا يتجاوز 2000 بكسل لتقليل حجم الموقع. لا تضع صورًا خاصة في مستودع عام إلا إذا كنت موافقًا على ظهورها للعامة.

## اختبار الموقع بعد التعديل

بعد كل تعديل:

1. احفظ الملفات في VSCode.
2. أعد تحميل الصفحة في المتصفح عبر `Ctrl + R` أو `Cmd + R`.
3. إذا لم يظهر التعديل، جرّب تحديثًا كاملًا عبر `Ctrl + Shift + R` أو `Cmd + Shift + R`.
4. إذا ظهرت مشكلة JavaScript، افتح أدوات المطور بالضغط على `F12` ثم تبويب **Console**.
5. لفحص صياغة JavaScript من الطرفية:

```bash
node --check public/app.js
node --check server.js
```

## نشر الموقع

### الخيار A: Netlify — الأسهل للموقع الثابت

هذا الخيار مناسب إذا أردت نشر الصفحة بسرعة دون خادم دائم.

1. شغّل الموقع محليًا وتأكد من أن كل شيء يعمل.
2. أنشئ نسخة جاهزة للنشر تحتوي على مجلد `public`.
3. افتح حسابك في [Netlify](https://www.netlify.com/).
4. من لوحة Netlify اختر **Add new site → Deploy manually**.
5. اسحب مجلد `public` إلى منطقة الرفع.
6. سيعطيك Netlify رابطًا عامًا للموقع.
7. من إعدادات الموقع يمكنك تغيير اسم النطاق أو إضافة نطاقك الخاص.

في هذا الخيار، ملف `server.js` لا يُستخدم في الاستضافة؛ لأن Netlify يقدّم ملفات `public` مباشرة.

### الخيار B: Render — تشغيل المشروع كاملًا عبر Node.js

هذا الخيار يستخدم `server.js` كما هو.

1. أنشئ مستودعًا جديدًا على GitHub.
2. ارفع محتويات مجلد المشروع إلى المستودع، ولا ترفع مجلد `node_modules` إن وُجد.
3. افتح [Render](https://render.com/) واختر **New → Web Service**.
4. اربط مستودع GitHub.
5. استخدم الإعدادات التالية:

```text
Runtime: Node
Build Command: npm install
Start Command: npm start
```

6. اختر الخطة المناسبة.
7. اضغط **Create Web Service**.
8. Render سيشغّل الموقع ويعطيك رابطًا عامًا.

الخادم يقرأ المنفذ الذي توفره الاستضافة من المتغير `PORT`، لذلك لا تحتاج إلى تعديل `server.js`.

### الخيار C: GitHub Pages — يحتاج تعديلًا بسيطًا

GitHub Pages لا يشغّل `server.js`، لكنه يستطيع عرض ملفات HTML/CSS/JS الثابتة.

1. أنشئ مستودعًا عامًا أو خاصًا على GitHub.
2. ارفع محتويات مجلد `public` إلى جذر المستودع، أو استخدم مجلد `docs`.
3. من إعدادات المستودع افتح **Pages**.
4. اختر الفرع `main` والمجلد الذي يحتوي `index.html`.
5. احفظ الإعدادات وانتظر إنشاء الرابط.

لا ترفع `server.js` وحده وتتوقع تشغيله على GitHub Pages؛ هذه الخدمة تعرض الملفات الثابتة فقط.

## ملاحظات الخصوصية

- التخصيص من زر «اكتبي قصتنا» يُحفظ محليًا في المتصفح ولا يُرسل إلى خادم.
- إذا استخدمت روابط صور خارجية، فقد يعرف مزود الصور أن الصورة تم تحميلها.
- إذا رفعت صورًا شخصية إلى استضافة عامة، فسيصبح رابط الموقع متاحًا لمن يملكه.
- لإهداء الموقع بشكل خاص، استخدم رابطًا غير منشور في وسائل عامة، أو استضافة تدعم الحماية بكلمة مرور.

## استكشاف الأخطاء

### تظهر صفحة بيضاء

تأكد من تشغيل الموقع بواسطة `npm start` أو `node server.js`، وليس بفتح `index.html` مباشرة من مدير الملفات. الموقع يحتاج خادمًا محليًا بسيطًا.

### المنفذ مستخدم

شغّل الموقع على منفذ آخر كما هو موضح في قسم **تغيير المنفذ**.

### الصور لا تظهر

تأكد من وجود الملفات داخل `public/images`، وأن المسارات تبدأ بـ `/images/`. إذا وضعت رابطًا خارجيًا، تأكد أنه يبدأ بـ `https://` ومتاح للعامة.

### تغييرات التخصيص لا تظهر

افتح الموقع في نفس المتصفح الذي حفظت فيه التخصيص. لمسح التخصيص وإعادة القيم الافتراضية، افتح Console واكتب:

```js
localStorage.removeItem('mydear-state');
location.reload();
```
